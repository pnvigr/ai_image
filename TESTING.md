# 🧪 ChartSense AI — инструкция по тестированию

Полный гайд: как запустить и как проверить **каждую** функцию. Делай по порядку —
займёт ~15 минут и покроет весь функционал.

---

## 1. Запуск

Нужно: **Node 20+** и **pnpm** (`npm i -g pnpm`).

```bash
pnpm install
pnpm dev
```

- Фронтенд: **http://localhost:5173**
- API: **http://localhost:4000** (проверка: http://localhost:4000/api/health)

Приложение работает **из коробки без всякой настройки** — в demo-режиме:
- нет ключа OpenRouter → ИИ отвечает реалистичным **mock-ответом**;
- нет MongoDB → данные хранятся **в памяти** (живут до перезапуска `pnpm dev`).

### 1.1. Рекомендуемый `.env` для полного теста

Чтобы проверить лимиты, токены и админку, создай файл `apps/api/.env`:

```env
JWT_SECRET=test-secret-123
ADMIN_EMAIL=admin@test.com        # этот email станет администратором
SUPPORT_CONTACT=Telegram: @your_handle
FREE_DAILY_LIMIT=3                 # маленький лимит, чтобы быстро увидеть «лимит исчерпан»
PAID_ANALYSIS_COST=1
# OPENROUTER_API_KEY=             # пусто = demo (mock). Вставь ключ → «живой» ИИ
# MONGODB_URI=                    # пусто = данные в памяти (сбрасываются при рестарте)
```

После изменения `.env` перезапусти `pnpm dev`.

> ⚠️ Без `MONGODB_URI` всё работает, но при перезапуске сервера аккаунты, история и
> токены **обнуляются**. Это нормально для локального теста. Для «как в проде» —
> подними MongoDB и впиши строку подключения.

### 1.2. Режимы (бейдж в шапке)

- **DEMO · mock-режим** (жёлтый) — нет ключа OpenRouter, ответы сгенерированы.
  В demo направление прогноза **случайное** — это специально (часть тезиса работы).
- **LIVE · <модель>** (зелёный) — задан `OPENROUTER_API_KEY`, работает реальная vision-модель.

## 2. Функционал и сценарии проверки

### A. Анализ скриншота (главная `/`)
Что делает: отправляет картинку графика в ИИ и показывает карточку-прогноз.

1. Загрузи скриншот графика **тремя способами** (проверь каждый):
   - клик по области загрузки → выбор файла;
   - перетаскивание файла (drag&drop);
   - **Ctrl+V** (вставка из буфера — удобно после «Ножниц»).
2. (Необязательно) впиши пару (напр. `GBP/USD`) и выбери экспирацию.
3. Нажми **Анализировать**.

✅ Ожидается: появляется карточка с полями **Время / Валютная пара / Направление
(UP/DOWN/NEUTRAL) / Экспирация / Уверенность (полоска %) / Описание** + теги-сигналы.
Внизу — бейдж модели (`mock` в demo). Вверху страницы — жёлтый дисклеймер «ИИ не
предсказывает рынок».

### B. Регистрация и вход
1. Кнопка **Регистрация** (в шапке) → введи email + пароль (от 6 символов) → «Зарегистрироваться».
2. ✅ Тебя перекинет на главную, в шапке появятся: баланс токенов, «История»,
   «Аналитика», email, «Выйти».
3. Нажми **Выйти**, затем **Вход** — войди тем же email/паролем.
4. Проверь ошибки: вход с неверным паролем → «Неверный email или пароль»;
   регистрация на занятый email → «Этот email уже зарегистрирован».
5. Обнови страницу (F5) — сессия сохраняется (токен в localStorage).

### C. История анализов (`/history`)
1. Залогинься и сделай 2–3 анализа на главной.
2. Открой **История** в шапке.
3. ✅ Анализы в списке. Вверху сводка: **Всего / Заходов / Винрейт / Σ payout**.
4. На карточке отметь исход:
   - **Заходил → Да**, затем **Win** или **Loss**, впиши **Payout** (напр. `1.85`),
     кликни вне поля.
   - ✅ Сводка винрейта пересчитывается.
   - Нажми **Заходил → Нет** — поля результата и payout **исчезают/обнуляются**.
5. Удали запись корзиной 🗑 → исчезает из списка.
6. Прямой заход на `/history` без логина → редирект на `/login`.

### D. Лимит бесплатного тарифа
(С `FREE_DAILY_LIMIT=3` это видно быстро. Лимит считается **для залогиненного** пользователя.)

1. Под аккаунтом сделай анализы, пока не упрёшься в лимит (4-й при лимите 3).
2. ✅ Появляется сообщение «**Дневной лимит бесплатных анализов исчерпан…**» и кнопка
   **«Использовать платную модель»**.

### E. Токены и платная модель (`/billing`)
1. Нажми **«Использовать платную модель»** (из шага D) ИЛИ просто переключись на платную.
2. Если токенов 0 → ✅ ошибка «**Недостаточно токенов**» + кнопка **«Пополнить баланс»**.
3. Открой **/billing** (клик по балансу в шапке или кнопка):
   - видны **пакеты токенов** (50 / 200 / 1000), баланс, контакт поддержки;
   - нажми **Оформить** на любом пакете → ✅ сообщение «Заявка создана… напишите в
     поддержку» и заявка появляется в **«Мои заявки»** со статусом **ожидает**.

> Реальной оплаты нет (это учебный проект): заявку подтверждает админ вручную (шаг F).

### F. Админка (`/admin`)
Доступна только аккаунту с `ADMIN_EMAIL`.

1. Зайди под `admin@test.com` (как в `.env`). При входе он автоматически получает роль **admin**,
   в шапке появляется ссылка **Админка**.
2. Открой **/admin**:
   - **Заявки на пополнение**: найди заявку из шага E → **Зачислить** → ✅ токены
     начисляются пользователю, статус → **fulfilled**.
   - **Пользователи**: впиши число в поле и **Начислить** (можно отрицательное — списать);
     кнопка **→ admin / → user** меняет роль.
3. Вернись под обычным пользователем (которому начислил токены) и сделай **платный**
   анализ → ✅ анализ проходит, **баланс в шапке уменьшается** на 1.
4. Не-админ, открывший `/admin`, → редирект на главную.

### G. Аналитика сделок (`/analytics`)
1. Открой **Аналитика** (нужно несколько анализов с отмеченными исходами — шаг C).
2. ✅ Видишь сводку винрейта и **разбивку по инструментам** (пара, входы, W/L, полоска винрейта).
3. Нажми **«Получить разбор»** → ✅ появляется текст-инсайт от ИИ + **рекомендованные
   тикеры** (из встроенного списка) + дисклеймер про незначимость различий.

### H. Тезис диплома (на что обратить внимание для защиты)
- Жёлтый дисклеймер на главной и в аналитике.
- В demo направление прогноза случайно → винрейт на отметках исходов стремится к ~50%.
- Аналитика прямо пишет, что различия между инструментами на малой выборке — шум.
  Это и есть вывод: **ИИ не даёт устойчивого предсказательного преимущества**.

## 3. Проверка API напрямую (для технической части защиты)

Полезно показать, что это полноценный REST API. Примеры (`curl`):

```bash
# здоровье
curl -s localhost:4000/api/health

# регистрация → вернёт {token, user}
curl -s -X POST localhost:4000/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"u@test.com","password":"secret123"}'

# анализ (демо-картинка 1x1). Подставь TOKEN из ответа выше, чтобы анализ привязался к юзеру
IMG='data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAAC0lEQVR42mNkYPhfDwAChwGA60e6kgAAAABJRU5ErkJggg=='
curl -s -X POST localhost:4000/api/analyze \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d "{\"imageDataUrl\":\"$IMG\",\"pairHint\":\"EUR/USD\"}"

# история, аналитика, тарифы
curl -s localhost:4000/api/analyses        -H "Authorization: Bearer <TOKEN>"
curl -s -X POST localhost:4000/api/analytics/insight -H "Authorization: Bearer <TOKEN>"
curl -s localhost:4000/api/billing/info
```

Полный список эндпоинтов: `auth` (register/login/me), `analyze`, `analyses`
(GET/PATCH/DELETE), `analytics/insight`, `billing` (info/topup/topup/mine),
`admin` (users/credit/role/topups/fulfill).

## 4. Проверка «как в проде» (один сервис)

Собрать всё и отдать фронт+API одним процессом:

```bash
pnpm build
SERVE_WEB=true PORT=4000 pnpm start
# открой http://localhost:4000 — это и фронт, и API
```

✅ `/` и любые маршруты (`/history`, `/billing` …) отдают приложение (SPA),
`/api/*` — это API. Так же будет работать на Railway (см. README → «Деплой»).
